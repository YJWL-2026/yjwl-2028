# 最优方案计算逻辑说明

> 文件编号：EMG-CALC-LOGIC-03
> 用途：用业务语言描述最优方案的计算过程，可直接作为技术要求文档的算法逻辑章节
> 对应模块：教（最优方案生成）、学（人机对比基准）、评（评分基准方案）

---

## 总览

最优方案的计算分为 **七个步骤**，按顺序执行：

```
灾害发生 / 场景启动
        │
        ▼
┌──────────────────┐
│ Step 1 灾害影响分析 │  → 输出：受影响路段列表、受影响车辆/货物/仓库清单
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Step 2 货物优先级排序│  → 输出：货物保障优先级队列
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Step 3 可用资源清点 │  → 输出：可调度车辆池、可用仓库池
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Step 4 方案生成     │  → 输出：3类候选方案（改道/转仓/放弃）
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Step 5 成本计算     │  → 输出：每个方案的运输+仓储+违约+损失总成本
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Step 6 方案比较与选择│  → 输出：最优方案 + 2-3个备选方案
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Step 7 评分计算     │  → 输出：四维评分 + 总分
└──────────────────┘
```

## Step 1：灾害影响分析

### 目的
确定灾害波及范围，标记受影响的路段、车辆、货物、仓库。

### 计算逻辑

**1.1 确定影响范围**

以地震为例：
- 读取灾害参数中的震中坐标 (lat, lng) 和影响半径 influence_radius_km
- 遍历所有道路网络中的路段，计算每条路段中点到震中的距离 d：
  - 若 d ≤ 影响半径 → 标记为"受影响路段"
  - 若 d > 影响半径 → 不受影响

**1.2 标记路段影响程度**

对每条受影响路段，按距离计算风险评分和延迟系数：

| 距震中距离 | 风险评分 risk_score | 延迟系数 delay_factor | 影响类型 |
|-----------|--------------------|-----------------------|---------|
| d ≤ 半径×30% | 0.8 ~ 1.0 | 3.0 | 若含桥梁→中断(blocked)，否则→限行(restricted) |
| 半径×30% < d ≤ 半径×60% | 0.4 ~ 0.8 | 2.0 | 限行(restricted) |
| 半径×60% < d ≤ 半径 | 0.0 ~ 0.4 | 1.5 | 减速通行(slow) |

- 含桥梁的路段在 risk_score > 0.6 时标记为中断（桥梁可能受损）
- 中断路段的延迟系数 = 无穷大（不可通行）

**1.3 标记受影响车辆**

遍历所有状态为 in_transit 的车辆：
- 若车辆当前所在节点位于受影响区域内 → 标记为"受困车辆"
- 若车辆原计划路线经过中断路段 → 标记为"需改道车辆"

**1.4 标记受影响货物**

遍历所有在途货物：
- 若原计划路线经过中断路段 → 标记为"受阻货物"
- 若目的地的收货客户在灾区范围内 → 标记为"目的受限货物"

**1.5 标记受影响仓库**

遍历所有仓库：
- 若仓库坐标在灾区范围内 → 按震中距离判定 damage_status：
  - d ≤ 半径×30% → 受损（容量折减50%）
  - 半径×30% < d ≤ 半径×60% → 受损（容量折减20%）
  - 半径×60% < d → 正常

### 输出

- 受影响路段列表（含风险评分、延迟系数、影响类型）
- 受困车辆列表
- 受阻货物列表
- 受影响仓库列表（含容量折减后值）

## Step 2：货物优先级排序

### 目的
确定货物的保障顺序，资源不足时先保障高优先级货物。

### 排序规则

按以下维度依次排序（多级排序）：

| 排序层级 | 维度 | 排序方向 | 说明 |
|---------|------|---------|------|
| 第1级 | priority_level | P1 > P2 > P3 | 优先级等级最高优先 |
| 第2级 | cargo_type | medical > supplies > urgent > normal | 同优先级内按货物类型 |
| 第3级 | deadline 紧急度 | 时间越短越优先 | 距deadline越近越优先 |
| 第4级 | value_yuan | 价值越高越优先 | 同等紧急度下保高价值 |

### 保障规则

| 优先级 | 保障要求 | 资源不足时 |
|--------|---------|-----------|
| P1（医疗/民生） | **必须保障**，不可放弃 | 即使调用全部资源也要保障 |
| P2（紧急件） | 优先保障 | 资源不足时最后放弃 |
| P3（普通件） | 尽力保障 | 资源不足时可优先放弃 |

### 输出

- 排序后的货物保障队列（从高到低）
- 每件货物的保障状态标记（must_deliver / preferred / optional）

## Step 3：可用资源清点

### 目的
盘点当前可用于应急调度的运力和仓储资源。

### 计算逻辑

**3.1 可调度车辆池**

遍历所有车辆，筛选可调度车辆：
- status = idle → 加入可调度池，可用载重 = 剩余载重
- status = in_transit 且需改道 → 加入可调度池（改道后继续执行任务），可用载重 = 当前剩余载重
- status = maintenance → 排除

**3.2 可用仓库池**

遍历所有仓库，筛选可用仓库：
- damage_status = normal → 可用容量 = remaining_capacity_m3
- damage_status = damaged → 可用容量 = remaining_capacity_m3 × 折减系数
- damage_status = closed → 排除

**3.3 可用道路网络**

构建灾害后的路网状态：
- 中断路段 → 从路网图中移除
- 限行/减速路段 → 通行时间 = 正常时间 × 延迟系数，保留在路网中
- 正常路段 → 通行时间不变

### 输出

- 可调度车辆清单（含编号、载重、当前位置、成本率）
- 可用仓库清单（含编号、剩余容量、仓储单价、是否冷链）
- 灾后路网状态（可用路段及其当前通行时间）

## Step 4：方案生成

### 目的
为受阻货物生成候选处置方案。

### 方案类型

系统为每件受阻货物生成以下 **三类候选方案**：

| 方案类型 | 动作 | 适用条件 |
|---------|------|---------|
| 改道(reroute) | 车辆变更路线，绕过中断路段送达目的地 | 目的地可达且车辆有剩余运力 |
| 就近转仓(warehouse_transfer) | 货物转存至就近可用仓库，灾后配送 | 附近有可用仓库且有剩余容量 |
| 放弃配送(abandon) | 放弃该货物配送，承担价值损失 | 仅限P3货物，P1/P2不允许 |

### 4.1 改道方案生成逻辑

对每件受阻货物：
1. 在灾后路网中，寻找从车辆当前位置到货物目的地的可达路径
2. 使用最短路径算法（Dijkstra）计算最优绕行路径
3. 若存在多条可达路径，按"成本最低"和"时效最快"各选一条，作为备选
4. 若目的地完全不可达（所有路径都中断）→ 改道方案不可行，转入转仓方案

### 4.2 就近转仓方案生成逻辑

对每件受阻货物：
1. 计算货物当前位置到所有可用仓库的距离
2. 筛选距离最近的 3 个仓库
3. 检查仓库是否有足够剩余容量容纳该货物
4. 评估转仓后的灾后配送可行性（灾后路网恢复后能否从仓库送达目的地）
5. 若仓库不可达或无容量 → 转仓方案不可行

### 4.3 放弃方案

对 P3 货物：
1. 标记为"放弃"，记录价值损失 = value_yuan
2. 仅在改道和转仓方案都不可行、或资源不足时触发

### 输出

- 每件受阻货物的候选方案列表（每个方案含类型、路径/仓库、预计成本、预计送达时间、风险评分）

## Step 5：成本计算

### 目的
计算每个候选方案的总成本，用于方案比较。

### 成本构成

```
方案总成本 = 运输成本 + 仓储成本 + 违约成本 + 货物损失成本 + 风险成本
```

| 成本项 | 计算方式 | 说明 |
|--------|---------|------|
| 运输成本 | 改道路径里程 × 车辆 cost_per_km + 过路费 | 含绕行额外里程 |
| 仓储成本 | 货物体积 × 仓储单价 × 预计存放天数 | 仅转仓方案产生 |
| 违约成本 | max(0, 实际送达时间 - 客户deadline) × 每小时违约金 | 超时才产生 |
| 货物损失成本 | 放弃货物的声明价值 value_yuan | 仅放弃方案产生 |
| 风险成本 | Σ 路径各路段 risk_score × 风险权重 × 货物价值 | 路径风险越高成本越高 |

### 成本计算示例

以一件受阻医疗货物为例：
- 原计划路线中断，需要绕行
- 改道路径里程 120km（原路径85km），车辆 cost_per_km = 8.5元
- 绕行后预计到达时间比deadline晚2小时，违约金 500元/小时
- 绕行路径经过1个高风险路段(risk_score=0.7)和2个中风险路段

计算：
- 运输成本 = 120 × 8.5 + 35(过路费) = 1055 元
- 仓储成本 = 0（不转仓）
- 违约成本 = 2 × 500 = 1000 元
- 货物损失成本 = 0
- 风险成本 = (0.7 + 0.4 + 0.4) × 0.1 × 80000 = 12000 元
- **方案总成本 = 1055 + 0 + 1000 + 0 + 12000 = 14055 元**

## Step 6：方案比较与选择

### 目的
为所有受阻货物选择总成本最低的处置方式，组合成完整的最优方案。同时在成本-时效-安全之间做帕累托权衡，生成备选方案。

### 6.1 货物-方案组合优化

对全部受阻货物，按优先级队列从高到低依次分配方案：

1. 取优先级最高的货物，列出其所有可行候选方案
2. 对每个候选方案，计算总成本（Step 5）
3. 选择总成本最低的方案
4. 更新资源池（消耗车辆运力、仓库容量）
5. 取下一优先级货物，重复以上步骤

> **关键规则**：资源被高优先级货物消耗后，低优先级货物只能使用剩余资源。这保证了 P1 货物必然被优先保障。

### 6.2 约束校验

组合方案完成后，校验以下约束：
- 车辆载重：每辆车装载的货物总重量不超过载重上限
- 仓库容量：每个仓库接收的货物总体积不超过剩余容量
- P1 货物：确认所有 P1 货物均有处置方案（改道或转仓），无 P1 货物被放弃
- 路段可达：所有方案选择的路径在灾后路网中确实可达

约束不通过 → 回退并重新分配（为冲突货物选择次优方案）。

### 6.3 备选方案生成

除最优方案外，系统额外生成 2 个备选方案，供教学对比：

| 备选方案 | 生成逻辑 | 特点 |
|---------|---------|------|
| 成本优先方案 | 提高成本权重，允许更多超时和放弃 | 成本最低，时效较差 |
| 时效优先方案 | 提高时效权重，调用全部可用资源保障时效 | 时效最好，成本较高 |

### 输出

- 最优方案（成本-时效-安全综合最优）
- 备选方案1（成本优先）
- 备选方案2（时效优先）
- 每个方案含：货物处置清单、总成本、总超时、车辆使用数、仓库使用数、放弃货物数

## Step 7：评分计算

### 目的
对最优方案（和学生方案）按四维评分矩阵打分，输出评分明细。

### 7.1 四维评分计算

#### 时效性得分（满分100，权重30%）

```
时效性得分 = 100 - 超时扣分

超时扣分计算：
  对每件货物：
    超时小时数 = max(0, 实际送达时间 - deadline) / 60  （分钟转小时）
    扣分 = 超时小时数 × 10  （每小时扣10分）
  总扣分 = Σ 所有货物的扣分
  时效性得分 = max(0, 100 - 总扣分)
```

| 情况 | 得分 |
|------|------|
| 所有货物按时送达 | 100 |
| 1件货物超时2小时 | 100 - 20 = 80 |
| 3件货物分别超时1/3/5小时 | 100 - (10+30+50) = 10 |

#### 经济性得分（满分100，权重25%）

```
经济性得分 = 100 × (基准成本 / max(实际成本, 基准成本))

  基准成本 = 场景配置的 benchmark_cost
  实际成本 = 方案总成本（Step 5 计算）
```

| 情况 | 得分 |
|------|------|
| 实际成本 = 基准成本 | 100 |
| 实际成本 = 基准成本 × 1.5 | 100 × (1/1.5) ≈ 67 |
| 实际成本 ≤ 基准成本 | 100（封顶） |

#### 可行性得分（满分100，权重25%）

```
可行性得分 = 资源合规分 × 0.6 + 路径可达分 × 0.4

  资源合规分：
    检查调用的车辆数 ≤ 可用车辆数 → 通过得60分，否则0分
    检查仓库使用量 ≤ 仓库容量 → 通过得40分，否则0分
    （资源合规分 = 两项之和，满分100，再乘0.6权重）

  路径可达分：
    检查所有路径不经过中断路段 → 通过得100分
    每经过1个中断路段 → 扣30分
```

#### 合规性得分（满分100，权重20%）

```
合规性得分 = 100 - 违规扣分

  违规扣分规则：
    P1货物被放弃 → 每件扣50分（严重违规）
    P1货物超时送达 → 每件扣20分
    P2货物被放弃 → 每件扣10分
    未优先保障医疗/民生物资 → 扣20分
```

### 7.2 总分计算

```
总分 = 时效性得分 × 30% + 经济性得分 × 25% + 可行性得分 × 25% + 合规性得分 × 20%

额外加减分：
  首次提交（未修改） → +5分
  超时提交 → -10分
  成功修正AI方案漏洞（策略二） → +10分
```

### 7.3 评分等级映射

| 总分区间 | 等级 | 评语定性 |
|---------|------|---------|
| 90-100 | A（优秀） | 卓越的全局掌控力 |
| 80-89 | B（良好） | 方案整体可行，有优化空间 |
| 70-79 | C（合格） | 基本完成决策，存在明显不足 |
| 60-69 | D（待改进） | 决策存在较大问题 |
| <60 | E（不合格） | 决策失败，需重新学习 |

## 学生方案对比逻辑

### 目的
学生提交方案后，将其与系统最优方案并排对比，展示差异。

### 对比维度

| 对比项 | 计算方式 | 展示方式 |
|--------|---------|---------|
| 成本差异 | 学生成本 - 最优成本 | 差值（正=学生更高） |
| 时效差异 | 学生超时总时长 - 最优超时总时长 | 差值（正=学生更慢） |
| 资源使用差异 | 学生使用车辆数 - 最优使用车辆数 | 差值 |
| 评分差异 | 学生总分 - 最优总分 | 差值（负=学生更低） |
| 四维得分差异 | 各维度学生分 - 最优分 | 雷达图叠加展示 |

### 差异分析文本生成

系统根据差异结果，自动生成对比分析说明（示例）：

> 你的方案总成本 52000 元，比最优方案高 6400 元（+14%）。主要差异在于：
> - 你多调用了1辆备用车（最优方案用3辆，你用了4辆）
> - 你的改道路径经过1个中风险路段，最优方案选择了风险更低的绕行
> - 评分方面，你的时效性得分与最优方案接近（82 vs 85），但经济性得分差距较大（72 vs 92）
> 
> 建议：在资源有限时，优先优化经济性，考虑是否可以合并配送以减少车辆调用。

## 三策略的适配差异

三种教学策略不改变上述计算逻辑的主体，仅影响以下环节：

| 环节 | 策略一（人机竞速） | 策略二（智能体对抗） | 策略三（有限预算） |
|------|-------------------|---------------------|-------------------|
| Step 3 资源清点 | 全量资源 | 全量资源，但引擎看不到隐藏干扰 | 资源受限（如车辆数减半） |
| Step 6 方案选择 | 正常选择最优 | 引擎可能选到被隐藏干扰影响的路径 | 选择"最不坏的"满意方案 |
| Step 7 评分 | 标准评分 | 增加"纠偏得分"（学生修正AI漏洞加分） | 增加"放弃决策合理性"子维度 |
| 最优方案展示 | 学生提交后才展示 | 引擎方案可能被学生修正 | 同时展示满资源最优和受限方案 |

### 策略三的"满意方案"逻辑

有限预算下不存在全局最优，系统计算两个基准：
- **满资源最优方案**（参考基准）：用全部资源计算，展示给学生作为"理想状态"
- **学生资源约束下的满意方案**：用受限资源计算，学生方案与此对比

学生方案评分时，与"满意方案"对比（而非满资源最优），避免因资源不足而评分过低。
