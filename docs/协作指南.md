## 1. 方案原理

```
你的电脑                  Gitee 云端仓库              好友的电脑
┌─────────┐              ┌──────────────┐            ┌─────────┐
│  本地代码 │  ── push ──▶ │  最新版本(云端) │ ◀── pull ──  │  本地代码 │
│         │  ◀── pull ── │              │  ── push ──▶│         │
└─────────┘              └──────────────┘            └─────────┘
```

**核心规则：每次开始编辑前先 pull（拉取最新），编辑完再 push（推送上去）。**

这样你们俩的代码始终通过云端同步，谁也不会覆盖谁。

## 2. 注册 Gitee

1. 打开 https://gitee.com （国内访问速度比 GitHub 快很多）
2. 点击右上角「注册」
3. 用手机号注册，设置密码
4. 注册后登录

> 建议：你和好友各注册一个账号。

## 3. 创建仓库

1. 登录后，点击页面右上角 **`+`** → **「新建仓库」**
2. 填写信息：
   - **仓库名称**：`emergency-decision`
   - **仓库介绍**：`应急决策智能体教学系统`
   - **可见性**：选择 **「私有」**（只有你俩能看到）
   - **初始化仓库**：**不要勾选**「使用 Readme 文件初始化」（我们已有代码）
3. 点击 **「创建」**

创建后，页面会显示一个仓库地址，类似：
```
https://gitee.com/你的用户名/emergency-decision.git
```
**请记下这个地址**，后面要用。

## 4. 上传代码

Git 仓库已在本地初始化完成（首次提交已创建）。现在把代码推送到 Gitee：

### 4.1 关联远程仓库

打开命令行（在项目根目录 `C:\Users\HW\WorkBuddy\2026-07-21-10-09-28`），执行：

```bash
# 把下面的地址换成你自己的仓库地址
git remote add origin https://gitee.com/你的用户名/emergency-decision.git

# 验证关联成功
git remote -v
```

### 4.2 推送代码

```bash
# 首次推送（-u 表示设置上游分支，以后就不用写了）
git push -u origin master
```

> 第一次推送时，会弹出登录窗口。输入你的 Gitee 用户名和密码（或个人访问令牌）。
> 如果嫌每次输密码麻烦，可配置免密：
> ```bash
> git config credential.helper store
> ```
> 下次输入一次密码后就会自动记住。

### 4.3 验证

刷新 Gitee 仓库网页，能看到 66 个文件就说明成功了。

## 5. 邀请好友

1. 在 Gitee 仓库页面，点击 **「管理」** → **「仓库成员管理」** → **「添加仓库成员」**
2. 输入好友的 Gitee 用户名或注册邮箱
3. 权限选择 **「开发者」**（可以 push 代码）
4. 点击 **「添加」**

好友会收到邮件通知，也可以直接访问仓库地址。

## 6. 好友获取代码

好友在自己的电脑上操作：

### 6.1 安装 Git

- **Windows**：下载 https://git-scm.com/download/win ，一路下一步安装
- **Mac**：终端执行 `brew install git` 或安装 Xcode 命令行工具

### 6.2 克隆代码

```bash
# 在好友想存放代码的目录下执行
git clone https://gitee.com/你的用户名/emergency-decision.git
```

输入 Gitee 账号密码后，代码会下载到 `emergency-decision/` 文件夹。

### 6.3 安装 Python 环境

好友需要安装 Python 3.10+ 才能运行项目：

```bash
# 进入项目目录
cd emergency-decision

# 安装依赖
pip install -r requirements.txt

# 运行服务器
python -m src.emergency_decision.api.app
# 或
python wsgi.py
```

访问 http://127.0.0.1:5000 即可看到系统。

## 7. 日常流程

**这是最重要的一节！** 你们俩每次编辑代码，都按这个流程来：

### 场景：你要修改代码

```
① 先拉取最新代码（防止好友改过你不知道）
   git pull origin master

② 修改代码（用你喜欢的编辑器/IDE）

③ 提交修改
   git add .
   git commit -m "说明你改了什么"

④ 推送到云端
   git push origin master

⑤ 通知好友："我改完了，你 pull 一下"
```

### 场景：好友要修改代码

好友也是一模一样的流程：
```
git pull origin master     # 拉取你的最新修改
# ... 修改代码 ...
git add .
git commit -m "好友改了什么"
git push origin master     # 推送上去
```

### 简单记忆

```
┌─────────────────────────────────────┐
│   开始编辑前 → git pull              │
│   编辑完成后 → git add .             │
│              → git commit -m "说明"  │
│              → git push             │
└─────────────────────────────────────┘
```

### 提交信息怎么写

提交信息要让人一看就知道改了什么：

```bash
# 好的写法
git commit -m "修复灾害查询页面导入按钮不显示的问题"
git commit -m "新增暴雨场景的预设数据"
git commit -m "优化移动端侧边栏滑动体验"

# 不好的写法（不知道改了啥）
git commit -m "update"
git commit -m "修改"
git commit -m "1"
```

## 8. 解决冲突

### 什么是冲突

如果你们俩**同时改了同一行代码**，后 push 的人会报错：

```
! [rejected]        master -> master (fetch first)
error: failed to push some refs
```

### 怎么解决

```bash
# 1. 先拉取最新代码（会提示有冲突）
git pull origin master

# 2. Git 会提示哪些文件冲突，打开这些文件，会看到：
<<<<<<< HEAD
你写的代码
=======
好友写的代码（云端版本）
>>>>>>> origin/master

# 3. 手动选择保留哪个（或合并两者），删掉 <<<<<<< ======= >>>>>>> 标记

# 4. 解决后重新提交
git add .
git commit -m "解决XX文件的冲突，保留了XX方案"
git push origin master
```

### 避免冲突的建议

- **沟通好分工**：你负责前端页面，好友负责后端逻辑，减少改同一文件
- **先 pull 再改**：每次开始前务必先拉取最新代码
- **频繁提交**：改一点就提交推送，不要攒一大堆
- **约好时间**：约定"上午你改、下午我改"，避免同时编辑

## 9. 常见问题

### Q1：忘记 pull 直接改了怎么办？

```bash
# 改完后先 pull 再 push
git pull origin master
# 如果有冲突，按上面「解决冲突」处理
git add .
git commit -m "你的修改"
git push origin master
```

### Q2：push 时提示 "permission denied"

说明你的账号没有 push 权限。检查：
- 是否用错了账号
- 仓库是否设为「私有」且好友未添加成员
- 运行 `git remote -v` 确认远程地址正确

### Q3：怎么查看历史修改记录？

```bash
# 查看提交历史
git log --oneline

# 查看某次提交改了什么
git show 提交ID前6位

# 在 Gitee 网页上也能看（更直观）
```

### Q4：改坏了，想回到之前的版本

```bash
# 查看历史提交
git log --oneline

# 回到某个版本（不删除之后的记录）
git reset --soft 提交ID

# 彻底回到某个版本（丢弃之后的修改）
git reset --hard 提交ID
# 然后强制推送
git push -f origin master
```

> ⚠️ `reset --hard` 会丢弃修改，谨慎使用！

### Q5：想看看好友改了什么

```bash
# 拉取好友的修改
git pull origin master

# 查看修改了哪些文件
git show HEAD --stat

# 查看具体改了什么内容
git show HEAD
```

### Q6：不想每次输密码

```bash
# 配置记住密码（永久）
git config credential.helper store

# 下次输入一次密码，以后就自动记住了
```

## 附：常用 Git 命令速查

| 命令 | 作用 |
|------|------|
| `git pull origin master` | 拉取云端最新代码 |
| `git add .` | 暂存所有修改 |
| `git commit -m "说明"` | 提交到本地仓库 |
| `git push origin master` | 推送到云端 |
| `git status` | 查看当前修改状态 |
| `git log --oneline` | 查看提交历史 |
| `git diff` | 查看未暂存的修改内容 |
| `git checkout -- 文件名` | 撤销某文件的修改（未add前） |

| 场景数据 | `scenarios/*.json` | 两人都可 |
| 文档维护 | `docs/` | 两人都可 |

> 分工不是绝对的，关键是**改之前先 pull，改完马上 push**。
